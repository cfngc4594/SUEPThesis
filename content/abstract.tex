\begin{abstract}

在线编程评测平台已经成为高校程序设计课程中常用的辅助工具，能够代替教师完成代码的编译、运行和结果判定。但在真实的教学场景下，多数现有平台只会返回 AC、WA、CE 等简短状态，学生看完往往依旧不清楚代码错在哪里、为什么会错。围绕这一问题，本文结合本科程序设计课程的实际使用情况，设计并实现了一个引入容器化执行与 AI 辅助反馈的在线编程评测平台。

平台采用 Next.js 与 Bun 搭建前后端，使用 PostgreSQL 配合 Prisma 管理题目和提交数据，编译运行环节交给独立的 Docker 容器处理。用户提交的代码会在受控的容器中完成编译、执行和测试用例比对，并通过资源限制与网络禁用相互隔离，避免相互影响或污染宿主机。前端编辑器基于 Monaco 实现，通过 Language Server Protocol 与容器内的 Clangd 对接，使学生在提交之前就能看到补全和诊断信息，不必依靠反复提交、再读编译输出的方式来定位问题。

AI 模块放在客观判题完成之后异步运行。系统会把提交的代码连同判题结果一起送给大模型，由模型从时间复杂度、空间复杂度、代码风格、可读性等维度给出分析，并以雷达图和文字反馈的形式呈现在提交详情页。AI 不参与判分，只作为客观判题之后的解释性补充。

围绕平台原型，本文完成了功能测试、判题正确性测试以及 AI 反馈效果分析。测试结果显示，平台对 AC、CE、WA、RE、TLE 五种判题状态都能给出与预期一致的返回，AI 模块对编译错误、答案错误、低效正确代码和风格较差代码也能给出与提交情形基本吻合的解释和建议。整体来看，本文实现的平台已经能够支撑一次完整的练习闭环，可以作为本科程序设计课程的教学辅助工具使用。

\end{abstract}

\begin{abstractEn}

Online programming judges are widely used in undergraduate programming courses, where they take care of compiling, executing and checking student code on behalf of the instructor. In practice, however, most existing platforms only return short verdicts such as AC, WA or CE, leaving students unsure of where their code went wrong or why. Motivated by this gap, this thesis designs and implements an online judge platform that combines containerised execution with AI-assisted feedback for undergraduate programming courses.

The platform is built on Next.js and Bun, with PostgreSQL and Prisma handling problems and submission data, while compilation and execution are delegated to dedicated Docker containers. Submitted code runs inside controlled containers that apply resource limits and disable network access, so that submissions cannot interfere with each other or with the host. The front-end editor is based on Monaco and is wired to in-container Clangd through the Language Server Protocol, which lets students see completions and diagnostics before submitting, instead of relying on repeated submissions and lengthy compiler output to locate issues.

The AI module runs asynchronously, after the objective judging stage has finished. The system sends the submitted code together with the verdict to a large language model, which produces an analysis along several dimensions, including time complexity, space complexity, code style and readability. The result is shown on the submission page as a radar chart together with textual feedback. The AI module never participates in scoring; it only provides an explanatory layer on top of the standard verdict.

A round of functional tests, judging-correctness tests and a case-based analysis of the AI feedback was carried out on the prototype. The platform produced the expected verdict for all five judging states under test (AC, CE, WA, RE, TLE), and the AI module gave reasonable explanations and suggestions for compilation errors, wrong answers, slow but correct solutions and code with poor readability. Overall, the implemented system can support a complete practice loop and can serve as an auxiliary tool for undergraduate programming courses.

\end{abstractEn}
