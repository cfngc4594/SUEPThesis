\begin{abstract}

在线编程评测平台已成为高校程序设计课程的重要基础设施，但多数教学型 OJ 仍以最终状态码返回为主，难以覆盖排队、编译、逐用例执行等过程信息，学生在定位问题时往往依赖反复提交。与此同时，判题安全隔离、异步吞吐能力与教学可解释反馈在同一系统中的协同实现存在明显工程难度。围绕这些问题，本文面向本科教学场景，设计并实现了一个基于云原生思路与 AI 辅助的一体化在线编程评测平台。

本文在判题主链路上采用提交受理与异步执行解耦方案：提交入口先创建状态为 QD 的记录并投递 Inngest 事件，由后台函数完成容器准备、源码上传、编译、逐用例运行与清理；执行阶段运行在受控 Docker 沙箱内，结合内存约束和网络隔离保障执行边界；状态变化通过 Soketi 通道实时回传前端，减少轮询开销。为提高可追踪性，数据层将判题信息拆分为 Submission、Judge、JudgeRun 三层模型，分别承载提交摘要、判题主状态和逐用例轨迹，实现从受理到终态的可复盘记录。

在教学支持侧，平台将反馈前移与反馈增强同时落地。提交前，前端工作区集成 Monaco 与 Language Server Protocol，通过容器化 Clangd 提供补全、诊断和签名帮助；提交后，AI 模块以异步方式生成复杂度、综合评分、代码风格、可读性、效率与正确性等多维分析结果，并给出可执行的改进建议，且与客观判题结果分离存储，避免解释模块影响裁决确定性。系统支持中英文界面与题面切换，AI 分析文本可随当前语言环境输出中文或英文反馈。验证结果表明，平台可稳定完成 AC、CE、WA、RE、TLE、MLE 等核心状态判定，异步链路与实时状态推送可连续工作；针对 \texttt{fork()} 滥用、超大内存申请和网络外联请求等恶意样例，系统也能在资源限制与网络隔离策略下阻断风险行为。相较以 UOJ 为代表、主要聚焦最终判题结论的传统教学 OJ，本文系统在保持客观判题稳定性的同时，提供了提交前语义诊断、提交中实时状态可视化与提交后多维解释反馈的一体化能力，体现了面向教学过程支持的系统特色与工程创新。

\end{abstract}

\begin{abstractEn}

Online programming judges are essential infrastructure in undergraduate programming education. However, many teaching-oriented OJ systems still focus on final verdict delivery, with limited visibility into intermediate stages such as queueing, compilation, and per-testcase execution, which weakens pedagogical feedback and troubleshooting efficiency. At the same time, combining execution isolation, asynchronous throughput, and explainable learning feedback in one system remains a non-trivial engineering challenge. To address these issues, this thesis designs and implements an integrated online programming evaluation platform based on cloud-native execution ideas and AI-assisted feedback.

The judging core adopts a decoupled accept-and-execute architecture. The submission endpoint first persists a QD-state record and emits an Inngest event; background functions then perform container preparation, source upload, compilation, per-testcase execution, and cleanup. Execution is isolated in controlled Docker sandboxes with memory constraints and disabled network access. Status transitions are pushed to the frontend in real time through Soketi channels, reducing polling overhead. For traceability, judging data is modeled in three layers: Submission, Judge, and JudgeRun, which separately capture submission-level summary, judging-level status, and testcase-level traces.

For instructional support, the platform implements both pre-submission and post-submission assistance. Before submission, the workspace integrates Monaco and the Language Server Protocol with containerized Clangd to provide diagnostics, completion, and signature help. After objective judging, an asynchronous AI pipeline produces multi-dimensional analysis including complexity, overall score, code style, readability, efficiency, and correctness, together with actionable improvement suggestions, while keeping explanatory output strictly separated from objective verdicts. The platform supports bilingual interface and statement switching, and AI feedback follows the active locale to generate Chinese or English reports. Experimental validation shows reliable handling of core verdict categories (AC, CE, WA, RE, TLE, MLE), stable asynchronous processing with real-time status updates, and effective containment of malicious samples such as uncontrolled \texttt{fork()} loops, excessive memory allocation, and outbound network requests under sandbox resource limits and network isolation. Compared with traditional teaching OJ systems represented by UOJ that mainly emphasize final verdicts, the proposed system preserves objective judging stability while adding integrated pre-submission semantic diagnostics, in-process real-time visibility, and post-submission multi-dimensional explanatory feedback, thereby improving interpretability and instructional value.

\end{abstractEn}
